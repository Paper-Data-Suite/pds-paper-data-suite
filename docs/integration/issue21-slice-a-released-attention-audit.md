## Slice A authority finding — STOP on unchecked factory loading

1. Core v0.6.6's **public** `inspect_core_provider_entry_points(provider_kind="module_operations")` returns metadata-only rows; it never returns an executable `EntryPoint` or validated profile. Suite #16 correctly projects that metadata as `declared_unvalidated`, not as authorization or publisher provenance.
2. Core's **public** `diagnose_core_providers(provider_kind="module_operations")` enumerates the entire group then calls `_diagnose_candidate` for **each installed candidate**; the latter invokes `entry_point.load()` and a zero-argument provider factory. The public function has no exact-name/distribution candidate-selector parameter. `_diagnose_candidate` is internal, not a supported targeted API.
3. Suite's `collect_module_operations_profile_diagnosis` intentionally stores only safe facts and discards `validated_profile`. Feeding a synthetic "valid" row or #16 metadata row into an invoker would **not** establish a qualified callable.
4. Decision: **do not** call the broad diagnostic from Suite #21's explicit per-owner action; **do not** build a second Suite entry-point loader using guessed imports or private Core functions. A narrowly scoped, Core-owned, public diagnostic/selection API (or separately approved equivalent) is required before a live Slice B invocation seam can be admitted. This is a **contract dependency**, not a claim that ScoreForm, Quillan, or Concord are defective.
5. A selected workspace and active year/class must be validated and authorized **outside** neutral Core v1 request validation. `ModuleOperationsRequest(workspace_root=None)` is structurally valid, so successful invocation alone cannot attest workspace authority. No default workspace discovery is allowed.

**Required Core contract:** allow deliberate evaluation of exactly one preselected `module_operations` candidate, with an unambiguous exact entry-point name and declared distribution, fail-closed duplicate/foreign/unknown provenance handling, public validated profile and bounded result. Selection must happen **before** `.load()` and factory execution, without touching unselected candidates. Core's public `invoke_module_attention(profile, request)` must remain the sole capability invoker after admission. Core entry-point diagnostics are not a sandbox; wheel provenance/authorization remain Suite's separate responsibility.

Plan → Prepare → Collect → Review → Score → Share is task order, not severity. **Generated packets are not returned pages; proposed attribution is not confirmed authorship.** Verify these two predicates against the exact released wheel, not ongoing #151 source work.

Until a reviewed per-owner partial signal exists, never describe any `evaluated_empty` with notices as “all clear,” and do not reinterpret `coverage="complete"` as exhaustive inspection.
- Core v1 validates owner of `ModuleOwnerActionRef` and `ModuleWorkRef` and rejects explicit wrong-class report content; Suite must also reject **classless** aggregates when displaying a specific class. Action references and work references remain inert; no automatic menu routing or publication.
- There is no publication, Grade, Notes, scan intake, roster change, startup provider callback, background refresh or on-disk cache under #21. Unknown/malformed provider objects, notices, errors and private strings must never enter display/repr/log/support export.

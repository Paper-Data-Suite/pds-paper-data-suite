## Four Windows installed negative journeys

The guarded runner reuses the previously independently qualified disposable E3A Python 3.11 installed Suite wheel and three exact published, authenticated Core 0.6.6 / ScoreForm 0.13.0 / Quillan 0.10.6 wheels. It first re-verifies the exact published wheelhouse, installed profile imports, native PDFium/ZXing and current action-time readiness, and that **no production Suite code changed** since the prior installed wheel. It never runs inside the source checkout: source harness imports do not authorize producers.

Each case begins with an entirely new, bounded, isolated OS-temp workspace and synthetic PDF, selects both physical pages by number, and completes only the first retention consent. Cases must terminate normally in actual installed interactive Teacher Home:

1. `missing_wheelhouse`: a nonexistent explicit local wheel directory is supplied; admission refuses before preparing Core requests or prompting for second consent.
2. `empty_wheelhouse`: an existing but empty, unauthenticated local wheel directory is refused; no Core dispatch is invoked.
3. `invalid_second_consent`: official-wheel admission and real two-page request preparation are reached, but the reply `APPROVE` is not `DISPATCH`; Core must return `cancelled`, with exactly **zero attempted physical pages** and no producer effects.
4. `unresolved_only`: a genuine two-page PDF with no QR is admitted for *read-only observation* and whole-file Core retention only. Fresh retained-byte preparation yields `no_dispatchable_pages`; teacher output displays both physical page positions and manual inspection guidance, with no second consent, no fabricated Core failure ID, no defer event and no producer dispatch.

Every case verifies one byte-identical Core-retained file, unchanged original and preexisting synthetic records, **no other new files**, no raw QR, absolute workspace/wheelhouse path, student label or ANSI escapes printed, and no grade-publication assertion. The scripts suppress raw errors and print only closed-vocabulary acceptance markers. A case failure is not a green result and should never trigger an automatic retry. Previously uncertain pages are not opened or used. Do not invoke this script against live student work.

**Important:** The two wheelhouse-denial cases occur *after* explicitly authorized Core custody; denial must not be mislabeled as rollback. The manual-only case intentionally retains the whole approved PDF, but performs no Core routing/producer action. This is **not** a live classroom/scanner qualification.

## Independent real installed Linux default-deny job

`.github/workflows/issue19-linux-installed-default-deny.yml` independently installs a built Suite 0.1.0 wheel plus the three exact authenticated published producer wheels in Python 3.11 on Ubuntu with PDFium/ZXing/Poppler. The Linux harness verifies native read-only observation of the committed synthetic PDS2 PDF as two candidate pages, then **requires** action-time `inspect_live_paper_admission` to return `unsupported_runtime` with an empty admitted module set. No Core retention or producer handler call is made; a full wheelhouse and parseable QRs are **not** dispatch credentials. This job is triggered for #19 branch pushes, pull requests and manual dispatch.

A Linux CI success is required independently of the Windows G2A skip before claiming cross-platform default-deny. Merely adding the workflow does not qualify Linux. CI may have external wheel-download prerequisites; report failures and correct the exact blocker rather than waiving the job.

## Qualification, ownership, limits

The source runner accepts only the exact clean reviewed #19 branch, exact source ZIP member digests and fixed additive scope; it runs Ruff, mypy and affected tests, checks staged whitespace and remote race, then commits/pushes on success **without merging**. Windows installed runner is separate and must execute after the source commit. Windows installed G2B and Linux CI must both pass before marking this slice accepted.

Suite only presents reviewed ephemeral results and never invents student identity, grades, persistent review queues or automatic replay.

# v0.1.0 Repository Governance Checklist

This checklist records the maintainer-approved repository governance required
before Paper Data Suite v0.1.0 may be promoted or published.

## Audit observation

At the issue #14 governance review, GitHub reported:

- `main` was not protected;
- required status-check enforcement was off; and
- the repository had no active rulesets.

Those observations describe the pre-release repository state, not the approved
target state.

## Approved `main` ruleset

Create and activate a GitHub branch ruleset targeting `main` with these
properties:

- require changes to arrive through a pull request;
- require **0 approving reviews** (the repository currently uses a
  solo-maintainer workflow);
- require the stable `release-gate` status check added by issue #14;
- do not permit force pushes;
- do not permit branch deletion;
- preserve the repository's squash-merge workflow;
- do not weaken the rule for ordinary pushes after v0.1.0 is published.

The purpose of the pull-request requirement is an auditable change/CI boundary,
not artificial self-review.

## Approved release-tag ruleset

Create and activate a GitHub tag ruleset targeting the release namespace:

```text
v*
```

The ruleset must prevent ordinary modification or deletion of release tags and
must restrict release-tag creation to the maintainer/release-authority path
configured for this repository.

Release publication must not depend on mutable or casually replaceable `v*`
tags.

## Private vulnerability reporting

Private Vulnerability Reporting was maintainer-confirmed enabled on August 25,
2026 before release identity promotion. The connected repository API does not
expose this toggle, so the audit preserves the distinction between maintainer
confirmation and independently readable ruleset state.

## Verification completed before promotion

On August 25, 2026, the pre-promotion governance gate was closed:

- the active `main release gate` ruleset was independently read from GitHub;
- it targets the default branch, requires pull requests with 0 approvals, requires
  exactly `release-gate`, blocks deletion/non-fast-forward changes, and has no
  bypass actors;
- the active `release-tag ruleset` was independently read from GitHub and targets
  `refs/tags/v*`, restricting creation, updates, deletion, and non-fast-forward
  changes for ordinary actors while retaining the organization-admin
  release-authority bypass;
- Private Vulnerability Reporting was maintainer-confirmed enabled. The connected
  repository API does not expose that security toggle, so this item is explicitly
  recorded as maintainer-confirmed rather than API-verified;
- PR #46 at pre-promotion head
  `b39a091e47726e9bb2630fd91046fe3ddc4aeb37` completed CI run #35 with all
  19 jobs successful, including `bootstrap-windows` and the required
  `release-gate`.

Repository settings remain external governance state. The source tree records
the verified evidence and policy but does not pretend repository settings are
source-controlled.

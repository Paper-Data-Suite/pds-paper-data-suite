## Real pip observation

An offline test creates a **disposable** virtualenv (`venv --copies --without-pip`) and installs two properly formed local wheels with `pip --python ... install --no-index --no-deps --no-compile`. The interpreter installed into the venv is not borrowed from the currently managed teacher installation. No real PDS classroom package is imported or executed. The wheelhouse and candidate venv live in pytest's private temporary directory, not the classroom workspace.

Real pip adds `direct_url.json` when installing wheel files from a local absolute path (PEP 610). Prior synthetic wheel fixtures did not include a valid hashed source `RECORD`, while genuine pip preserves those source `RECORD` hashes in installed metadata. Slice 23 uses correctly hashed wheel `RECORD` fixtures and asserts successful **strict** audit of the generated launcher `RECORD`, installed source and metadata, as well as local-wheel origin.

## Strict trust boundary

`inspect_locked_pip_direct_url` accepts only a bounded JSON object with:

- `url` matching the exact `file://` URI of the independently authenticated locked wheelhouse file;
- `archive_info.hash` matching `sha256=<signed wheel digest>`;
- `archive_info.hashes.sha256` matching the identical signed digest.

It rejects other keys, duplicate keys, remote/VCS/editable links, unrecognized schemes and mismatching wheel paths or digests. It performs **no download, file acquisition or import**. The generated metadata still has no independent signing authority; the verified wheelhouse lock is the authority. The entire `direct_url.json` contents are included in the installed `RECORD` verification and inventory hash, and `direct_url.json` is optional when the installer does not produce it.

The module does **not** trust an arbitrary local wheel because it appears in a pip metadata file. Whole-environment identity, native interpreter provenance, publisher delegation, protected continuity and activation remain separately required. Strict script `RECORD` verification stays mandatory in this slice's acceptance tests.

## Boundaries and remaining work

A real-pip *fixture* using minimal wheels is not equivalent to qualifying the latest released Core, ScoreForm, Quillan, Concord, Meridian, Vitrine or Portia wheels on Windows ARM64/x64. Stage installation with exact signed wheels, validate native executable provenance with a separate authority, qualify Core/provider contracts, and establish a protected active installation history before integrating production launch and updates.

The offline pip test intentionally uses `--no-compile` because generated bytecode is not part of the signed-wheel file inventory. Other pip versions may produce unsupported metadata; they should fail closed until separately qualified. No private signing keys belong to production artifacts.

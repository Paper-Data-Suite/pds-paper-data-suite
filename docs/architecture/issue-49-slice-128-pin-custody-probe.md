# Issue #49 — Slice 128: Native fixed-path publisher-pin custody observation

**Parent:** `90c249f497a5d94483f4c52715257e9952ba9183`. This is a non-authorizing, read-only Win32 probe, not an installer or a provisioning interface.

The new `pds_windows_publisher_pin_custody_probe` asks Windows for the actual ProgramData Known Folder and inspects the fixed `Paper Data Suite/service-state/publisher-pin-v1.json` path. It holds four OS handles (ProgramData, application directory, service-state directory, policy file) across the read. It opens existing objects for read/metadata access only, with `FILE_SHARE_READ` and reparse-point inspection; checks directory/file kind, owner/DACL and policy-file hardlink count; rejects unknown ACE forms and unprivileged mutating allow ACEs; and reads at most 512 bytes. The pure Slice 126 canonical parser validates any observed policy claim.

A missing policy record is the normal unprovisioned CI state. Whether the policy is absent or parsed, the output always denies publisher authentication, independent provisioning, rollback protection and installation authorization. `--install` and every other argument are refused. Build products remain outside the repository; the existing x64 and native ARM64 Windows jobs require the negative-security diagnostic to execute on the matching CPU. ARM64 cross-compile alone never passes for native runtime acceptance.

**Security limits:** An ACL check is a point-in-time observation, **not independently authenticated** provenance of whoever created the file. A pin file that appears protected is **not provisioned** by this code and is **not rollback resistant**. The pure parser cannot establish that a policy was issued by an authorized administrator, that an older revision has not been replayed, or that existing protected installation custody is secure. A privileged and independently administered trust-root provisioning authority, protected monotonic revision witness, authenticated native service, durable transactions and real ordinary-user attack tests remain mandatory. This slice performs **no installation**, no service registration, no ACL change, no write, no receipt issuance and no module activation.

A Windows native build failure or unexpected positive authorization state blocks acceptance. Existing Slice 121–127 diagnostics and their CI gates must remain intact. A green build cannot be presented as production security approval.

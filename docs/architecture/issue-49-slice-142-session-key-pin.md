# Suite #49 — Slice 142: session-bound key pin against valid alternate signatures

**Exact parent:** `26292c6c310b0dcfe3b1c70bd0786edfe29a3f44`.

## Gap closed in the disposable cryptographic experiment

Slice 141 demonstrated real RSA-3072/PSS/SHA-256 signature verification and rejected a changed payload, changed signature, and unrelated public key with the original signature. That does **not** catch an attacker who substitutes both the candidate key and a mathematically valid **self-signed** replacement signature. The application must not treat an artifact-supplied key as an independently trusted publisher.

Slice 142 adds a narrow **session pin** to the independent ephemeral Windows verifier. The administrator-side CI harness captures SHA-256 of the original test public-key SPKI bytes before it starts the **separate verifier process**, then passes that 64-digit lowercase fingerprint explicitly. The verifier requires it, computes the presented public key's SHA-256, and compares exact digest bytes with fixed-time equality before allowing RSA-PSS validation.

It validates the genuine pair, rejects a deliberately invalid pin, and generates a second ephemeral RSA key and its own correctly signed payload. The second pair MUST pass bare RSA-PSS as a positive control but fail session-pinned verification. The harness fails if any test is unavailable, alters a protected file, returns installation approval, or changes the established source authority boundaries.

## Security limitations — no production authority

This is **not publisher authentication** and **not a production trust root**. The administrator harness initially derives the fingerprint from a public key generated by the same disposable signer. That is not independently provisioned or authenticated to a real PDS release publisher. The experiment shows resistance only to *post-pin* key substitution; a malicious signer or forged initial pin remains in scope for a separate independently administered trust-root design. Signature verification by itself cannot prove release origin, authorize installation, defend against rollback, attest service identity, or authenticate an ordinary user or administrator.

The test runs only on a GitHub-hosted ephemeral Windows runner under an elevated administrator token. It writes no private key to disk, registers no service, modifies no existing production PDS directory, performs no ordinary user ACL weakening, and supplies no production installer or rollout capability. Every report retains publisher provenance, rollback protection, production release verification, and installation authority as explicitly false.

The normal source-only qualification runner never invokes the write-capable sandbox. The existing `issue49-sandbox-os-parent-denial.yml` workflow automatically runs this experiment when either revised PowerShell file changes; a successful run should print `SLICE142_EPHEMERAL_SESSION_PIN_BLOCKS_SELF_SIGNED_SUBSTITUTION` alongside prior Slice 141 and ACL acceptance markers.

## Further required work

An independently established public-key trust anchor, signed release metadata and approved identity/rotation scheme, rollback-resistant custody, recoverable privileged installer, real installed service, and negative security acceptance under a separately authenticated ordinary user all remain outstanding. Session pinning is an engineering test, **not** a release acceptance, publisher approval, or installation decision. No production state is created or updated by this slice.
